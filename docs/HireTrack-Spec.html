Product & technical specification

HireTrack AI v1

Nov 14, 2026Aravinda KaranamBuilt live in class

A web app that helps job seekers tailor their resume to each job with AI, find fresh postings near them every morning, and track every application in one place.

React + ViteFastAPISQLAlchemy + AlembicSQLiteOpenAI APIClaude (switchable)Adzuna APIJWT + bcrypt
1 · Overview

Why it exists

Problem

Candidates send the same resume to every job without knowing which skills each posting expects, and track applications across scattered spreadsheets and notes.

Goal

One place to check resume fit for a job, discover new postings nearby, track applications from Wishlist to Offer, and see how the job hunt is going.

Target user

Students and professionals actively applying for jobs.

2 · Scope

What v1 includes

In scope

  • Signup, login and logout
  • Resume upload (PDF) or paste
  • AI Resume Match
  • Application pipeline on a Kanban board
  • Job-hunt dashboard
  • Daily Job Feed from the Adzuna API, ranked against the active resume

Out of scope

  • Social login (Google, LinkedIn)
  • Email or calendar sync
  • Scraping job boards. LinkedIn, Indeed and Glassdoor forbid it and offer no public job-search API
  • Job sources other than Adzuna; auto-applying
  • Cloud deployment
  • Password reset, email verification, account deletion from the UI
  • OCR for scanned PDFs
3 · Core features

Six features

3.1

Authentication

  • Email and password; emails stored lowercased
  • Passwords 8–72 bytes
  • Each user sees only their own data
3.2

Resume

  • PDF (max 2 MB, text via pypdf) or pasted text, max 20,000 characters
  • Immutable: each upload is a new row and becomes active
  • Switch back to an older resume any time
3.3

AI Resume Match

  • Fit score 0–100, missing skills, 3 tailored bullets
  • Company and role read from the posting, confirmed by the user
  • Save as a Wishlist application; 20 matches per day
3.4

Application pipeline

  • Wishlist → Applied → Interview → Offer, plus Rejected
  • Drag between stages; dates set automatically
  • Interviews attached to an application
3.5

Dashboard

  • Applications by stage
  • Interviews this week, Monday to Sunday in the browser's timezone
  • Response rate = replied ÷ sent
3.6

Daily Job Feed

  • One saved search: keywords, country, city, radius, remote OK
  • New postings each morning, quick-scored by the AI provider
  • Save to pipeline or dismiss
6 · System architecture

Three tiers, one gatekeeper

A React single-page app calls a FastAPI REST API over JSON with a JWT. Only the backend reads and writes SQLite and calls the AI provider (OpenAI by default, Claude when switched) and Adzuna, so API keys and the database never reach the browser.

AI integration

  • Provider from AI_PROVIDER: openai (default, official openai SDK) or anthropic
  • Model IDs and prices are placeholders until chosen with the evaluation set
  • Strict JSON schema output, then checked again with Pydantic
  • 12 s timeout, 1 retry: a match finishes within about 15 s
  • Resume and posting go in delimited blocks, treated as data, never as instructions

Failure handling

  • Refusal, invalid output or exhausted retries → 502 "try again"; nothing is saved
  • Adzuna failure → saved as the run's last_error, shown on the Job Feed tab, retried next run
3.6 · Daily Job Feed

From 75 postings to a ranked shortlist

Each user saves one search profile. Every morning the backend fetches new postings near them and ranks them against the active resume, using one AI request per run.

Quick score, not a full match

Adzuna returns a shortened description, and the app never opens posting pages itself. The feed score is labelled “Quick score”. For a full match, open the posting, paste its description, and run AI Resume Match with company, role and link pre-filled.

Runs on your machine

There is no cloud deployment, so APScheduler runs inside the backend. A morning missed while the backend was off is caught up the next time it starts.

Privacy and terms

Only keywords and location go to Adzuna, never the resume. The Job Feed tab shows Adzuna's required attribution and links to each posting on its own site.

3.4 · Application stages

Moves set the dates the dashboard needs

Any stage can move to any other, so the Kanban board never blocks a drag. The services layer fills in applied_date and responded_at as cards move, and the response rate is computed from those two dates.

7 · Database design

Seven tables, all owned by a user

Every table except interviews carries a user_id; interviews belong to a user through their application. Times are stored in UTC and the schema is created only through Alembic migrations.

Constraints

  • One active resume: partial unique index on resumes(user_id) WHERE is_active = 1
  • UNIQUE on applications.match_id and job_postings.application_id
  • UNIQUE (user_id, source, external_id) keeps dismissed postings from returning
  • CHECK on stage, status, source, fit scores and radius

Ownership rule

  • Every query filters by the current user_id
  • Interviews load through a join to applications
  • Any referenced ID is first loaded with the user filter; not found → 404, never 403

SQLite gotchas

  • Turn on PRAGMA foreign_keys = ON per connection, or cascades are ignored
  • No ON UPDATE: updated_at comes from SQLAlchemy onupdate=
  • Foreign keys aren't indexed automatically: index interviews.application_id
When this is deletedWhat happens
A user (admin/script only)Resumes, matches, applications, search profile and job postings are deleted; interviews go with their applications
An applicationIts interviews are deleted; a posting saved as it keeps its data with application_id set to NULL
A matchThe application saved from it stays; match_id becomes NULL
A resumeNot possible in v1. resume_id foreign keys use NO ACTION so deleting a whole user still works
Old NEW / DISMISSED postingsRemoved by the daily run after 30 days; SAVED postings are kept

6.1 · API

Endpoints under /api/v1

Every route except signup and login needs a valid JWT. Lists aren't paginated, because one person's job hunt stays small.

MethodPathPurpose
POST/auth/signup · /auth/loginCreate an account or log in; returns a token
GET/auth/meCurrent user
GET · POST/resumesList resumes; upload a PDF or paste text (becomes active)
POST/resumes/{id}/activateMake an older resume active
POST · GET/matches · /matches/{id}Run a match against the active resume; read past matches
GET · POST/applicationsList (optional ?stage=); create, optionally from match_id
GET · PATCH · DELETE/applications/{id}Read, edit (including stage) or delete
GET · POST/applications/{id}/interviewsList or add interviews
PATCH · DELETE/interviews/{id}Edit or delete an interview
GET/dashboard?tz=Asia/KolkataStage counts, interviews this week, response rate
GET · PUT/search-profileRead or save the Job Feed search
GET/jobsFeed postings (default NEW), best first, plus last run and error
POST/jobs/refreshRun the feed now; 429 within an hour of the last refresh
POST/jobs/{id}/save · /jobs/{id}/dismissCreate a Wishlist application, or hide the posting
StatusMeaning
400Validation failed
401Missing or expired token
404Not found, or belongs to someone else
409Conflict: no active resume, email already taken
429Over the match or refresh limit, or too many failed logins
502The AI call failed; nothing was saved

Errors share one shape: {"error": {"code": "NO_ACTIVE_RESUME", "message": "Add a resume before running a match."}}

4 · Non-functional · 8 · Testing

Security, performance, tests

Security

  • bcrypt hashes; HS256 JWT signed with JWT_SECRET, valid 24 h
  • Token in localStorage: simple, but never render user or AI text as HTML
  • Logout clears the browser only; a stolen token works until it expires
  • 5 failed logins per email per 15 minutes
  • AI provider and Adzuna keys live only in the backend .env

Performance and portability

  • Pages load in about a second; a match returns in under 15 s
  • Feed scoring runs in the background: 60 s timeout, 2 retries
  • UTC timestamps, JSON as TEXT and Alembic migrations make the move to PostgreSQL a URL change plus one migration

Testing

  • pytest and TestClient on a temporary SQLite file, with fake AI and jobs clients
  • Stage rules, dashboard maths and timezones, constraints
  • User B gets 404 for every one of user A's IDs
  • AI timeouts, refusals and invalid output; feed duplicates, refresh limit, catch-up, cleanup
  • About 5 real resume/job pairs checked by hand before the demo
